# Аудит формул, методик и источников

## Цель

Каждый расчёт в Geolog GASRATIO&Pixler должен иметь воспроизводимую цепочку:

**методика → формула → версия профиля → входы и единицы → контрольный пример →
расчёт → график/отчёт → источник и ограничения применения**.

Аудит не предназначен для хранения или распространения полных текстов чужих публикаций.
В репозитории хранятся библиографические сведения, DOI/каталожные ссылки, вычислительные
выражения, короткие методические пояснения, контрольные примеры и результаты проверок.

## Уровни доказательности

| Уровень | Когда используется | Требование к отчёту |
|---|---|---|
| `primary_publication` | Haworth, Pixler, Jorden–Shirley, Rehm–McClendon и другие профили с первичной публикацией | Указывать автора/работу, версию formula profile и ограничения |
| `public_patent_or_standard` | Формулы нормализации из открытых патентов/стандартов | Указывать идентификатор публикации, reference conditions и параметры |
| `secondary_crosscheck` | Методика подтверждается открытыми вторичными материалами | Использовать как screening/supporting evidence и явно обозначать уровень |
| `workbook_reproduced` | Воспроизводимая историческая/прикладная методика по контрольной книге | Разрешено для ОПУС; помечать workbook-derived / pending field validation |
| `engineering_default` | Проектные пороги/детектор, требующие полевой калибровки | Нельзя представлять как универсальную опубликованную методику |

## Строгий контур

Для Haworth/Pixler/DEXP/DEXPC и открытых нормализующих формул обязательны:

- versioned `FormulaProfile`;
- точное expression;
- перечень required inputs и единиц;
- bibliographic source / DOI / publication ID;
- численный control example;
- boundary/zero/NaN tests;
- UOM-conversion tests;
- совпадение live и batch расчётов;
- запись формулы/версии/источника в Report Passport.

Профиль без этих полей не регистрируется в `FormulaProfileRegistry`.

## ОПУС — облегчённый, но прозрачный контур

ОПУС не блокируется отсутствием открытого первичного текста для каждой исторической
формулы/палетки. Для него достаточно воспроизводимости и прозрачной маркировки:

- pinned SHA-256 исходной контрольной книги;
- versioned JSON-profile;
- golden control row;
- boundary tests для палеток;
- публичные cross-checks там, где они доступны;
- явные errata;
- отметка `workbook_reproduced` или `secondary_crosscheck`;
- отдельная отметка `engineering_default` для detector thresholds;
- в отчёте — только предварительная/скрининговая интерпретация.

ОПУС не должен обозначаться как `primary-source verified`, если такой уровень не подтверждён.

## Права и цитирование

Проект не включает полные тексты защищённых публикаций без соответствующего права.
Для доказуемости расчёта достаточно хранить:

- стандартную библиографическую запись;
- DOI, патентный номер или публичную каталожную ссылку;
- необходимое математическое выражение и параметры;
- краткое фактическое описание назначения методики;
- собственные контрольные примеры и тесты.

В отчётах воспроизводится только необходимая ссылка/цитирование и собственные результаты
расчёта, а не большие фрагменты исходной публикации.

## Графики и интерпретационные интервалы

Интервал УВ на печатном графике должен иметь:

- цветную полосу на фактической глубине;
- текстовый маркер, чтобы смысл сохранялся в grayscale;
- короткую выноску с **типом флюида**: газ, газ-конденсат, лёгкая нефть, нефть,
  тяжёлая/остаточная нефть или смешанный/неопределённый тип;
- интервал глубины и пометку, что интерпретация предварительная;
- автоматическое размещение внутри printable bounds без наложения соседних выносок;
- отсутствие автоматического угадывания, если методики дают неоднозначный результат.

Цвет не является единственным носителем смысла.

## Автоматические проверки

Канонический inventory строится в
`geoworkbench.services.formula_method_audit.build_method_audit_manifest()`.

CI проверяет, что все зарегистрированные sourced formula profiles присутствуют в audit manifest,
а ОПУС находится в менее строгом, но разрешённом screening tier.
