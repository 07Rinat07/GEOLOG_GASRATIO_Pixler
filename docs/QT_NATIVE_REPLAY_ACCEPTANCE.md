# CI/Qt #544 — проверка доказательств ручного Windows replay

Проблема #544 — периодическое нативное завершение Python/Qt (`0xC0000005`
и ранее `0xC0000374`). Зелёный повтор CI **не доказывает устранение причины**.
Ручной workflow не входит в три обязательных Windows Release Gate.

## Наблюдение от 9 ноября 2026

Post-merge [Release Gate 42462681087](https://github.com/07Rinat07/GEOLOG_GASRATIO_Pixler/actions/runs/42462681087)
для `main` `726a22f00d7cb10858cf2986289d932ad298fefb` неоднократно завершился
нативной ошибкой `0xC0000374` во время очистки Qt после теста Masterlog.
Точные изменения PR #855 до слияния прошли все три gates; это не заменяет
post-merge проверки. Локально соответствующая группа из 54 файлов прошла, в том
числе с версиями PySide и NumPy из CI.

Отдельный [CDB replay 42519002234](https://github.com/07Rinat07/GEOLOG_GASRATIO_Pixler/actions/runs/42519002234)
использовал временный диагностический код коммита
`ba27fdb4c869dff958c2629649fb463baa741d56`. Он зафиксировал необработанное
`0xC0000005` в `PySide::SignalManager::retrieveMetaObject` при создании
`QVBoxLayout` в `_rebuild_page_layout`, вызванном при создании `MainWindow`
в тесте окна просмотра восстановления архива. Сохранены Python-стек, нативный
стек и минидамп тестового процесса. Артефакты Actions имеют ограниченный срок
хранения; минидамп может содержать данные памяти и требует безопасного обращения.

В дополнительном [replay 42519953983](https://github.com/07Rinat07/GEOLOG_GASRATIO_Pixler/actions/runs/42519953983)
на диагностическом коммите `bc1f9d6b163e495acf552a67a040fd73757f1db6` CDB при
нарушении доступа показал Python-объект типа `PySide6.QtWidgets.QWidgetItem`
в регистре `rbx` внутри `retrieveMetaObject`. В последующем
[replay 42520828031](https://github.com/07Rinat07/GEOLOG_GASRATIO_Pixler/actions/runs/42520828031)
на коммите `e63aa967492ea55636495178726488bd9af505da` адрес этой обёртки не
совпал с адресами двух элементов, непосредственно извлечённых перед созданием
layout. Это наблюдения одного пути под отладчиком, а не доказательство того,
где объект был создан или повреждён. Оба прогона остановлены на исключении;
их статус workflow не является успешным завершением целевого набора тестов.

В [replay 42521864940](https://github.com/07Rinat07/GEOLOG_GASRATIO_Pixler/actions/runs/42521864940)
на диагностическом коммите `44f1e1ddee13c3fed7e15d8fcb08d32fc0a91e85` эта
обёртка присутствовала среди объектов Python до сбоя. На момент трассировки
`shiboken6.isValid` вернул `True`; её нативный указатель совпал со значением
регистра `rsi` при остановке CDB. Проверка `isValid` отражает состояние привязки,
а не гарантирует, что нативная память и время жизни объекта корректны. Трассировка
влияет на выполнение; происхождение обёртки и первопричина остаются неизвестными.

Статус workflow `success` в этом **специальном** прогоне означает выход CDB
после захвата исключения, а не прохождение всех тестов: целевой процесс был
остановлен отладчиком. Это не штатный replay с `results.json` и не Release Gate.
Наблюдение определяет место остановки, но не доказывает первопричину или то,
что `0xC0000005` и `0xC0000374` имеют одну причину. Не считать #544 исправленной.
Далее: изучить жизненный цикл Qt-объектов и минидамп, воспроизвести возможное
исправление без изменения набора проверок и отдельно подтвердить gates PR и main.

## Запуск на настоящем Windows runner

1. В GitHub Actions выбрать **Windows Qt native replay (manual)**,
   затем **Run workflow**, ветку `main`, режим `both` и число повторов `4`.
2. Зафиксировать **полный 40-символьный SHA** коммита, с которым стартовал
   workflow. Не подменять его текущим `main`, если HEAD успел измениться.
3. После завершения скачать артефакт `qt-native-replay-<run_id>-<attempt>`.
   Должны присутствовать `results.json`, `native-runtime.json` и
   отдельные журналы завершённых дочерних процессов. При аварии скачать
   `qt-native-dumps-<run_id>-<attempt>`, если минидампы были сформированы.
4. Из корня checkout того же SHA выполнить команду с папкой распакованного
   артефакта (в ней должны находиться два JSON-файла):

```powershell
.\.venv\Scripts\python.exe -m tools.check_qt_replay_evidence --artifact-dir "C:\path\to\qt-replay" --commit "<full-40-character-sha>"
```

## Значение результатов

- Код `0`: все **запланированные** дочерние прогоны завершились успешно,
  версия Windows/Qt и SHA источника подтверждены по артефактам. Это только
  успешное наблюдение, **не исправление #544**.
- Код `1`: завершённый повтор содержит хотя бы одну ошибку, в том числе
  нативную аварию. JSON показывает фактически наблюдённые сценарии сбоя.
- Код `2`: запуск неполный либо данные противоречивы/не читаются. Если
  неполный отчёт валиден, в JSON будет `diagnostic_status="incomplete"`;
  неверный SHA, подменённый selector или отсутствующий журнал отвергаются
  без JSON в stdout.

Проверка отвергает символические ссылки на файлы JSON и дочерние журналы,
а также Windows reparse-point файлы: требуется обычный файл в каталоге
распакованного артефакта. Это не защита от конкурентной замены файлов
после проверки: запускайте анализ на доверенном неизменяемом снимке.

Проверяющий инструмент **только читает** сохранённые артефакты. Он не
запускает сценарии, не обращается к содержимому скважин, не меняет LAS/WITS/ГТИ,
не очищает staging, не отключает тесты, не подтверждает первопричину native
access violation и не заменяет ручной анализ журнала и минидампа.

Три обязательные Windows Release Gate и отдельная проверка `main` после
слияния остаются без изменений.
