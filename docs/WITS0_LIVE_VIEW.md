# WITS0 live monitor

## Назначение

Вкладка **Монитор** отображает read-only представление growing WITS0 Dataset. Она не изменяет
`AcquisitionSession`, не останавливает TCP-приём и не обходит `AcquisitionController`.

## Текущие значения

Пользователь выбирает каналы слева. Для каждого канала показываются последнее конечное значение,
единица и качество. Если в новой строке значение отсутствует, предыдущее корректное значение
остаётся видимым с состоянием `missing`. Состояние `stale` определяется по UTC-времени получения.

## Оси времени и глубины

Режим **Автоматически** использует активный индекс Dataset. Режимы **Время** и **Глубина**
используют реальный индекс при его наличии. Если вторичной оси нет, live monitor создаёт только
read-only ось:

- UTC-время из `AcquisitionRecord.received_at`;
- глубину из подтверждённой semantic depth curve.

Производная ось не добавляется в Dataset и не сохраняется в проект.

## Auto-follow, pause-view и история

Auto-follow показывает заданное окно до последней точки. Отключение auto-follow разрешает
масштабирование и прокрутку истории. **Пауза просмотра** фиксирует количество видимых строк, но
acquisition продолжает принимать и записывать данные. Возобновление переводит представление к
актуальному хвосту.

## Downsampling

`select_visible_samples()` ограничивает количество точек в выбранном окне, сохраняет пики и
NaN-разрывы. Исходный Dataset и append-only records не изменяются. Внизу вкладки показывается
число исходных и отрисованных точек.

## Маркеры качества и разрывов

На график выводятся source-sequence gaps, большие интервалы оси, invalid values и missing spans.
Источник marker определяется из append-only record provenance. Маркеры являются диагностикой и не
заменяют решения специалиста ГТИ.

## Ограничения и приёмка

Операторский dashboard группирует совместимые каналы по технологическим панелям и автоматически
разделяет несовместимые единицы на соседние треки с независимым X-autoscale. Настройки выбранных
каналов, оси и окна сохраняются в workspace.

Transient LIVE PREVIEW хранит последние 2000 кадров. Его Dataset/session projection также
ограничивается: при достижении верхнего порога runtime пересобирается из последнего bounded-окна,
не изменяя постоянную acquisition-сессию. Если старые кадры уже вытеснены из памяти, текущий
backfill переносит только retained preview-окно; явный выбор/восстановление более ранней границы
из raw-файла остаётся частью WITS-MEM-01 и не считается закрытым этим ограничением памяти.
Обязательны Windows Qt smoke test и проверка на реальном anonymized GSWITS raw-потоке.
