# План проекта

## Новое направление: импорт GeoScape II GS2

Цель — открыть `.gs2` напрямую, восстановить исходные TIME/DEPTH и измерительные каналы и
передать их в существующий `Dataset` без изменения исходного файла.

### Этап 1 — безопасный контейнер [выполнено]

- [x] отдельный модуль `importers/gs2`, распознающий формат по ZIP-сигнатуре;
- [x] проверка единственного `GS2.mdb` и наличия `GS2#*.db`;
- [x] защита от path traversal, дубликатов, шифрования, zip bomb и превышения лимитов;
- [x] временная распаковка с автоматическим удалением;
- [x] выбор GS2 в универсальном импорте, отдельная команда и drag-and-drop;
- [x] RU/KK/EN диагностика и тесты синтетических контейнеров.

### Этап 2 — метаданные Access [базовый адаптер выполнен]

- [x] читать только временную копию `GS2.mdb` через Qt ODBC/Microsoft Access Engine в read-only;
- [x] диагностировать отсутствие QODBC/ACE и несовпадение разрядности без блокировки импорта;
- [x] извлекать `WELLS`, `FORMULAS`, список таблиц и сохранять доказательства в provenance;
- [x] подтверждено на СГ-8: `FORMULAS.RESGID=N` относится к каналу `SN`, а не к массиву
  `GS2#N`; формальных Access relationships и единиц каналов в этом MDB нет;
- [x] дополнять подтверждённые имена формул и сырые S-коды существующим Sensors `legacy_gid`;
- [ ] добавить версионные проекции для других схем GeoScape и обезличенные Access fixtures.

### Этап 3 — таблицы данных GeoScape II

- [x] подтверждено на файле СГ-8: все `GS2#*.db` являются валидными таблицами Paradox 7.x;
- [x] проверены схемы, размеры записей, цепочки блоков, NULL, NUMBER и TIMESTAMP;
- [x] `GS2#101.db`: TIME + DEPTH + 206 каналов, 10 001 строка, 3000–5000 м с шагом 0,2 м;
- [x] выбранная таблица направляется в существующий потоковый Paradox reader/import dialog;
- [x] автоматически объединять части `GS2#1.db`, `GS2#1_1.db`, … после проверки непрерывности TIME;
- [ ] добавить обезличенные golden fixtures и проверки повреждённых/обрезанных записей.

### Этап 4 — интеграция Dataset и сетка

- [x] строить TIME/DEPTH `DatasetIndex`, `CurveData`, provenance и QC для выбранной таблицы;
- [x] передавать результат через общий Import Review в проект;
- [x] обогащать semantic bindings подтверждёнными именами `FORMULAS`, единицами/мнемониками
  Sensors и ссылкой на строку Access; неоднозначные S/SB-коды не угадывать;
- [x] определять фактический шаг медианой положительных приращений, устойчиво к редким пропускам;
- [x] сохранять исходную сетку; ресэмплинг на 0,2 м выполнять только явной derived-операцией;
- [ ] подтвердить Gas Ratio/Pixler и LAS/Excel export на каналах, сопоставленных через `GS2.mdb`.

### Этап 5 — приёмка

- [ ] проверить файл СГ-8 и минимум два GS2 из других версий GeoScape;
- [ ] сверить выбранные каналы и диапазоны с экспортом GeoScape Exporter в LAS/Excel;
- [ ] проверить C1–C5, суммарный газ, TIME/DEPTH, разбиение файлов, отмену и очистку temp;
- [ ] считать поддержку завершённой только после воспроизводимого совпадения индексов и значений.

Текущий пользовательский результат: контейнер можно открыть, выбрать отдельную таблицу либо
безопасную многочастную TIME-серию и импортировать её в обычный `Dataset`. При наличии совместимого
ACE/QODBC импорт получает паспорт скважины, 17 связей `FORMULAS.RESGID → S-код` и Sensors fallback;
без драйвера сохраняет исходные имена и выдаёт конкретную инструкцию. Следующий этап — golden
fixtures других версий и сверка с LAS/Excel. Подробный контракт: [GS2_IMPORT.md](GS2_IMPORT.md).

## Критерий приёмки

На внешнем мониторе и ноутбуке правая команда редактирования полностью видна. При нехватке места
сначала скрываются подписи, затем второстепенные команды появляются в **«⋯»**. Значок можно
растянуть по одной или двум осям, сохранить через **Ctrl+S** и получить те же размеры после
повторного открытия, в preview, PDF и печати.
