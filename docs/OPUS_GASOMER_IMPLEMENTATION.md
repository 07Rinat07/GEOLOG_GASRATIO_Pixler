# Инструкция по реализации профиля «ОПУС Газомер»

Статус: `OPUS-01…07` завершены; требуется независимая полевая валидация `OPUS-08`.
Актуально на 30 августа 2026 года.
Связанные задачи единого плана: `OPUS-01`–`OPUS-08` в
[PROJECT_PLAN.md](PROJECT_PLAN.md).

Этот документ фиксирует результаты анализа текущего ОПУС, предоставленной книги
`Газомер.xls`, реального LAS и обсуждения с пользователем. Он не является вторым roadmap:
приоритеты и статус работ ведутся только в `PROJECT_PLAN.md`. При расхождении документов
приоритет имеют: проверяемые исходные данные и тесты → этот контракт → паспорт формул →
пользовательские инструкции.

## 1. Цель и границы

Нужно добавить самостоятельный профиль **«ОПУС Газомер»**, который по синхронным C1–C5 на
всей глубине скважины:

1. выделяет газовые/углеводородные проявления в динамике;
2. рассчитывает пять показателей книги для каждого допустимого глубинного отсчёта;
3. агрегирует результаты только внутри реально выделенного интервала;
4. подписывает предварительный тип проявления: газ, газоконденсат, нефть, газонасыщенная
   нефть, остаточная/окисленная нефть либо неопределённый тип;
5. показывает заказчику формулы, входные единицы, качество данных, голоса показателей,
   источники и ограничения вывода.

Профиль является **дополнительным вариантом отчёта**. Он не заменяет и не изменяет уже
работающие Gas Ratio, Haworth, Pixler, текущий исторический ОПУС и стандартный отчёт.
Автоматическая категория остаётся скрининговой гипотезой и не доказывает промышленную
продуктивность, насыщение водой или фазовый состав без ГИС, испытаний и контекста бурения.

## 2. Что установлено по текущей реализации

Текущий профиль `opus-lukyanov-c1-c5-relative-1987-1997` нормирует компоненты на
`C1 + C2 + C3 + C4 + C5`, рассчитывает четыре исторических показателя и ищет единственный
класс в пересечении перекрывающихся диапазонов. Если пересечение неоднозначно, отчёт выводит
явно помеченную независимую гипотезу Haworth/Pixler.

На предоставленном реальном LAS текущий алгоритм сформировал 64 интервала-кандидата, но только
один получил прямой класс ОПУС; 63 были классифицированы резервом. Для 63 из 64 интервалов
`OPUS_1_5` оказался вне всех диапазонов, для 61 из 64 — `OPUS_K1_3`. Среди 1412 строк
аномалий нулевые значения встречались в C2 в 1072 строках (75,9%), C3 — в 662 (46,9%),
C4 — в 588 (41,6%), C5 — в 835 (59,1%). Это объясняет массовую неоднозначность, но само по
себе не доказывает отсутствие УВ-пластов.

Вывод: текущий исторический профиль нельзя молча заменить. Для воспроизведения практического
расчёта книги нужен отдельный профиль с другим знаменателем, пятым показателем и правилом
голосования, а для многокилометрового LAS — иной способ выбора интервала.

## 3. Проверенная структура книги `Газомер.xls`

Внешний источник: пользовательская книга `Газомер.xls`, SHA-256
`bd70ce36ac9f99f56267c7fc24b51bf4ba0a26e2ffb86e768b282e1bd5201818`.
Книга не копируется в репозиторий и не изменяется; этот документ содержит достаточную
транскрипцию для воспроизводимости. Это прикладной источник пользователя, а не первичная
публикация метода.

На листе `отчет по газу` используются относительные компоненты:

```text
p1 = 100 × C1 / TotalGas
p2 = 100 × C2 / TotalGas
p3 = 100 × C3 / TotalGas
p4 = 100 × C4 / TotalGas
p5 = 100 × C5 / TotalGas
```

Здесь `TotalGas` — отдельный канал «Сумм.Газ», а не сумма C1–C5. Это принципиальное отличие
от уже реализованного исторического профиля. В одной строке книги рассчитаны:

```text
ОПУС1 = (p1 × p2) / (p2 + p3)²
ОПУС2 = (p1 × p2 × p3) / (p2 + p3 + p4)³
ОПУС3 = (p1 × p2 × p3) / 3
ОПУС4 = (p1 × p2 × p3 × p4 × p5) / 5
ОПУС5 = ((p2 × p3 × p4 × p5) / p1) × (p2 + p3 + p4 + p5) × 100
```

Соответствие названий неодинаково:

| Книга `Газомер.xls` | Текущий проект | Решение |
|---|---|---|
| ОПУС1 | примерно `OPUS3` | в новом профиле хранить как `OPUS_GM_1` |
| ОПУС2 | примерно `OPUS4` | хранить как `OPUS_GM_2` |
| ОПУС3 | `OPUS_K1_3` | хранить как `OPUS_GM_3` |
| ОПУС4 | `OPUS_1_5` | хранить как `OPUS_GM_4` |
| ОПУС5 | аналога в runtime нет | добавить только как `OPUS_GM_5`, источник — книга |

Книга переводит каждый показатель в код класса и берёт `MODE` пяти кодов. Коды:

| Код | Подпись книги |
|---:|---|
| 1 | остаточная/окисленная нефть |
| 2 | нефть |
| 3 | горючий газ |
| 4 | водорастворённый газ |
| 5 | газоконденсат |
| 6 | газонасыщенная нефть |
| 7 | не определено |

Точные границы всех пяти преобразований перенесены напрямую из `Y4:AC4` в
`opus_gasomer_profile_v1.json` и закреплены golden-тестами ниже/на/выше каждой границы.
В ячейке `AB4` подтверждена ошибочная конструкция `AB2>AB5=250000`: Excel вычисляет её как
`(AB2>AB5)=250000`, поэтому ветвь класса 1 недостижима для обычных чисел. Production-профиль
использует явное включительное условие `AB2 >= 250000`. Исправление записано в fixture metadata
как errata `GASOMER-AB4-CHAINED-COMPARISON`, а не внесено незаметно.

Контрольная строка самой книги использует legacy MAX: `TotalGas=9`, `C1=3`, `C2=2`,
`C3=C4=C5=1`. Она даёт `OPUS_GM_1…5 = 0,6666667; 0,09375; 2743,4842;
203221,0537; 5080526,3425`, голоса `2,2,2,2,1` и итоговый класс 2 — «Нефть».
Идентичность первичного файла подтверждена SHA-256, книга открывалась только для чтения.

## 4. Почему книгу нельзя растянуть на всю скважину

Классификационная строка книги берёт независимые максимумы C1, C2, C3, C4 и C5 из фиксированных
диапазонов. На длинном интервале максимумы могут относиться к разным глубинам, поэтому возникает
синтетический состав, которого ни в одной пробе не было. Часть формул ограничена жёсткими
конечными строками, поэтому более поздние глубины могут вообще не участвовать в расчёте.

Запрещено переносить этот подход на 0–5000 м одной формулой. Основной профиль должен считать
синхронно по строкам и агрегировать голоса после выделения короткого геологического интервала.
Для проверки совместимости допускается отдельный режим **«Газомер — legacy MAX по выбранному
интервалу»**, но только для одного короткого, явно выбранного оператором интервала. Результат
такого режима помечается как совместимость с книгой и не смешивается с основным результатом.

## 5. Принятые решения

| ID | Решение | Обоснование |
|---|---|---|
| OPUS-D01 | Существующие методы и форматы не менять | ОПУС — дополнительный вариант отчёта |
| OPUS-D02 | Исторический ОПУС и «ОПУС Газомер» — разные versioned profiles | разные знаменатели, число показателей и правила класса |
| OPUS-D03 | `% об.` — рабочая единица; ppm поддерживается с точным переводом `1 % = 10 000 ppm` | пользователь работает и с `%`, и с ppm |
| OPUS-D04 | Порог фона `0,1 % об.` не блокирует поиск и класс автоматически | фон зависит от раствора, дегазации, разбавления и режима бурения |
| OPUS-D05 | `0,1 %` показывается как рекомендация источника/предупреждение доверия | сохраняется доказательная оговорка без ложного отрицания пласта |
| OPUS-D06 | Аномалии ищутся по локальному адаптивному фону | медиана по всей скважине не отражает смену условий по глубине |
| OPUS-D07 | Ноль/значение ниже предела обнаружения означает «показатель недоступен», а не «вне класса» | отсутствующий компонент нельзя превращать в отрицательное доказательство |
| OPUS-D08 | ОПУС5 включается только в профиль «Газомер» | формула известна из книги, но не подтверждена первичной публикацией |
| OPUS-D09 | Класс определяется по синхронным строкам и поддержке внутри интервала | исключает искусственный состав из максимумов разных глубин |
| OPUS-D10 | Ничья голосов не разрешается произвольно | итог — «неопределённо/конфликт», с показом голосов |
| OPUS-D11 | Haworth/Pixler показывается отдельным независимым результатом | резерв нельзя выдавать за прямой результат ОПУС |
| OPUS-D12 | «Водорастворённый газ» требует внешнего подтверждения | один газовый состав не доказывает водонасыщение |
| OPUS-D13 | «Продуктивный» не выводится только по C1–C5 | требуются ГИС/испытания и операционный контекст |

## 6. Целевой алгоритм по всей глубине

### 6.1. Подготовка данных

1. Разрешить DEPTH, C1–C5 и независимый TotalGas через semantic/UOM resolver.
2. Не изменять source arrays. Создать производные `% об.` с provenance исходной кривой и
   преобразования единиц.
3. Различать отсутствующее значение, измеренный ноль и значение ниже LOD.
4. Если независимый TotalGas отсутствует, профиль «Газомер» не подменяет его суммой C1–C5
   молча. Допустима только явно выбранная политика с записью в паспорте.

### 6.2. Выделение интервалов

Для каждой глубины оценить локальный устойчивый фон TotalGas в скользящем окне, исключая
аномальные пики. Признаки кандидата: абсолютное превышение `ΔTG`, устойчивый robust z-score и
локальный контраст. При почти нулевом фоне знаменатель контраста ограничивается снизу пределом
обнаружения TotalGas, а не универсальным `0,1 %`.

Размер окна фона, минимальная мощность интервала, допустимый разрыв и пороги являются
версионированными параметрами профиля. Начальный рабочий вариант сглаживания — 1,0 м
(5 отсчётов при шаге 0,2 м), но это прикладная настраиваемая политика, а не формула Лукьянова.

### 6.3. Расчёт строки

Для каждой синхронной строки внутри кандидата:

1. вычислить `p1…p5 = 100 × Ci / TotalGas`;
2. проверить положительный знаменатель, конечность и LOD требуемых компонентов;
3. вычислить `OPUS_GM_1…OPUS_GM_5`;
4. преобразовать каждый доступный показатель в код по versioned band table;
5. сохранить не только код, но и исходное число, применённую границу и причину недоступности;
6. получить строковый класс только при уникальной моде; при ничьей сохранить конфликт.

### 6.4. Агрегация интервала

Итоговый класс — уникальный класс с максимальной поддержкой среди валидных строк интервала.
Отчёт обязан показать:

- число всех и валидных строк;
- долю поддержки итогового класса;
- распределение голосов по классам;
- доступность каждого из пяти показателей;
- долю строк ниже LOD/с пропусками;
- локальный фон, пик, `ΔTG`, контраст и robust z-score;
- прямой результат «ОПУС Газомер» и отдельный результат Haworth/Pixler;
- предупреждения о качестве, низком фоне, неподтверждённом ОПУС5 и конфликте методов.

Минимальная доля поддержки должна быть параметром профиля и до полевой калибровки не может
выдаваться за опубликованный универсальный порог.

## 7. Контракт качества и применимости

Для каждого компонента и TotalGas конфигурация должна хранить предел обнаружения и, если
доступно, предел количественного определения. Пока приборные LOD не заданы, программа должна
показывать это как отсутствие калибровочных метаданных, а не считать любой ноль истинным
отсутствием газа.

Статус качества имеет три независимые оси:

- **обнаружение проявления** — достаточно ли динамики TotalGas;
- **доступность расчёта** — достаточно ли синхронных C1–C5/TotalGas выше LOD;
- **доверие к типу флюида** — достаточно ли согласованы строки и показатели.

Низкий абсолютный фон может снижать доверие, но не удаляет интервал и не запрещает расчёт.
Фраза «ОПУС неприменим при фоне ниже 0,1%» не должна использоваться как безусловное правило.

## 8. Архитектурные границы

Рекомендуемое размещение:

- новый versioned profile и чистые функции — в расчётном слое без Qt;
- детектор интервалов — отдельная чистая служба, пригодная для исторического ОПУС и Газомера;
- report model хранит оба независимых результата и evidence;
- UI только выбирает профиль/параметры и отображает статус;
- exporter читает готовую report model и не пересчитывает формулы;
- исходные и стандартные производные кривые не перезаписываются;
- идентификаторы новых кривых используют `OPUS_GM_*`, чтобы не столкнуться с `OPUS3` и
  `OPUS4` текущего профиля.

Сериализуемый паспорт должен включать `profile_id`, `profile_version`, формулы/хэш таблицы
границ, UOM mapping, LOD, параметры детектора, source curve IDs, временную/глубинную привязку,
warnings и версию приложения.

- калибровать окна/пороги отдельно от формул и версионировать изменения;
- запретить объявлять профиль валидированным без достаточной выборки.

## 10. Обязательные тесты

1. Эквивалентные `%` и ppm дают одинаковый результат.
2. Нулевой/`NaN`/ниже LOD знаменатель даёт недоступный показатель, не бесконечность.
3. Пять формул совпадают с контрольным примером книги.
4. Каждая граница класса проверена непосредственно ниже, на границе и выше.
5. Ничья не превращается в случайный класс.
6. Независимые максимумы на разных глубинах не создают искусственный состав.
7. Низкий фон, включая `0,01 %` и ниже, не удаляет контрастный интервал.
8. Смена локального фона по стволу не скрывает более позднее проявление.
9. Отсутствие TotalGas, C2–C5 или LOD создаёт объяснимое предупреждение.
10. Исторический ОПУС и стандартный Gas Ratio/Haworth/Pixler побайтно/численно не меняются.
11. Прямой ОПУС и Haworth/Pixler не подменяют друг друга в отчёте.
12. Экран, XLSX, DOCX и PDF совпадают по границам, классу, поддержке и формулам.
