# История изменений

Здесь фиксируются только крупные продуктовые изменения. Подробная история отдельных исправлений
доступна в Git; отдельные release notes, build manifests и AI-отчёты не создаются.

## Unreleased

- WELL-04: литологический редактор подключён к production write-path готовности переводов:
  явный язык оригинала, source revision и зависимости глубины/литотипа сохраняются атомарно;
  оригинал получает persisted `reviewed` source-marker с `translation_revision=0`, переводы —
  `missing/draft/stale`. Legacy/fallback не получает неявный provenance, а старые controller-
  вызовы tracked-интервала наследуют сохранённый source вместо возврата в legacy-путь.
- WELL-04: project v32 сохраняет по полю и языку состояния `missing`, `draft`, `reviewed`,
  `stale`, язык и ревизию исходника, ревизию перевода и ревизии зависимостей; проекты v31
  открываются с пустым реестром и не получают ложную отметку проверки.
- WELL-04: атомарный workflow начинает новую ревизию черновика, проверяет только актуальный
  перевод и точечно помечает `stale` при изменении связанного исходного поля или зависимости.
- WELL-04: контроллер проектной сессии применяет статусы с content revision, dirty и
  защищённой историей undo/redo; ошибочные и пустые изменения не создают команду.
- WELL-04: project v33 сохраняет независимые ревизии конкретных авторских полей; изменение
  одного исходника атомарно делает stale только связанные с ним переводы и поддерживает undo.
- WELL-04: добавлена read-only сводка готовности переводов по языкам и выбранному диапазону
  глубин; она отдельно считает missing/draft/reviewed/stale, не включает соседние интервалы и
  fail-safe выявляет расхождение текущих ревизий без мутации сохранённого статуса.

- WELL-03: менеджер интерпретаций получил вкладки RU/KK/EN для name/description набора и
  label/comment интервала. Глубины, тип и цвет вводятся один раз; таблица и список показывают
  язык приложения с fallback, не записывая legacy-текст как перевод.

- WELL-03: project v31 сохраняет RU/KK/EN для названия и описания набора интерпретации, а
  также подписи и комментария каждого интервала. Миграция v30 добавляет пустые словари без
  изменения legacy-текста; контроллер валидирует все языки до мутации и сохраняет undo/redo.

- WELL-03: быстрый редактор стратиграфического интервала из планшета/Masterlog теперь
  возвращает название и описание RU/KK/EN вместе с единственным набором глубин, ранга, кода,
  цвета и параметров подписи; выбор справочника заполняет все доступные языки.

- WELL-03: редактор кальциметрии и ЛБА получил независимые вкладки RU/KK/EN для описания
  свечения и заключения геолога. Общие числовые результаты и стандартизованные признаки
  вводятся один раз, оба языковых словаря проверяются до изменения пробы, а legacy-fallback
  не записывается как русский перевод.

- WELL-03: редактор стратиграфических интервалов получил общие вкладки RU/KK/EN для названия
  и описания. Глубины, код, ранг, цвет и параметры подписи задаются один раз; справочник
  заполняет все доступные названия, а add/update сохраняет языковые версии атомарно без
  превращения legacy-fallback в русский перевод.

- WELL-03: единый редактор пробы шлама получил вкладки описания RU/KK/EN. Черновики каждого
  языка сохраняются при переключении, один готовый шаблон добавляет согласованные тексты во
  все три версии, а подтверждение записывает многоязычное описание одной операцией. Формат
  project v30 хранит порядок вставок, уникальный ID блока, ID/версию шаблона и точный снимок
  RU/KK/EN, поэтому обновление каталога не переписывает сохранённые описания. Редактор
  показывает список вставок; выбранный маркированный блок удаляется сразу из всех трёх языков,
  сохраняя ручные дополнения, а неоднозначные старые записи остаются защищёнными.

- WELL-03: редактор литологических интервалов получил независимые вкладки RU/KK/EN. Выбор
  заводского шаблона заполняет три согласованные версии, а add/update передаёт их контроллеру
  одной атомарной операцией. Редактирование прочих полей legacy-интервала не записывает fallback
  как русский перевод.

- WELL-02 завершён: числовые обновления, геология, отдельные анализы, сохранённые профили
  поставщиков с явным подтверждением перепривязки и перенос пользовательских рисунков прошли
  обязательные Release gates и интегрированы в `main`.

- WELL-02: добавлен project v28 для well-level истории поздних/отдельных анализов шлама.
  `analysis_update_history` сохраняет источник и SHA-256, выбранные поля, точный fill-only diff
  и hashes состояния скважины до/после. Миграция v27 → v28 добавляет пустой ledger без
  изменения существующих данных; повреждённые, неизвестные и не-fill-only audit записи
  отклоняются. Проверки покрывают round-trip, migration и malformed payload.

- WELL-02: дополнение свободных интервалов литологии и состава шлама по явно выбранному
  JSON-профилю поставщика; ручные интервалы, описания и переводы сохраняются. Коллизии
  кодов разделяются по профилям с показом экспортных кодов. Общий откат чисел и геологии,
  исходный LAS и снимок профиля в истории project v27; миграция v26 сохраняет прежние данные.

- WELL-02: числовое обновление подключено к окну ежедневного LAS на RU/KK/EN.
  Новый суффикс добавляется отдельным выбором; пропуски и исправления применяются только
  по отмеченным ячейкам «было → стало». Неизменённые данные и исходные LAS сохраняются,
  сбой подготовки/регистрации источника откатывается. История изменений сохраняется
  в project v26 с миграцией v25; автосохранение и backup используют штатный workflow.
  Ошибка записи оставляет полный результат dirty в памяти и не сообщает об успешном сохранении.
  Геологическое дополнение и профили поставщиков остаются следующими частями WELL-02.

- WELL-02: добавлена повторная проверка числового плана без записи данных. Изменение
  Dataset, имени/хэша источника, счётчиков или отображённого diff требует нового анализа.
  Проверка сокращённого preview не разрешает применение исправлений.

- WELL-02: добавлен внутренний анализ числовых обновлений с раздельными счётчиками
  новой глубины, заполнения пропусков и исправлений и ограниченным immutable diff.
  Анализ сохраняет исходные данные; NaN не очищает проект, ноль не считается пропуском.
  Общая проверка LAS отклоняет несовместимые depth domains.

- 6 сентября 2026, локальный инкремент WELL-02: предварительный анализ суточного LAS
  привязан к состоянию исходного и целевого Dataset, включая значения вне перекрытия,
  единицы и происхождение кривых. Изменённые данные нельзя применить по старому preview;
  неудачная повторная проверка и отмена окна сбрасывают подтверждение. Старые audit SHA-256
  сохранены, временная память хэширования массивов ограничена. Добавлены regression tests
  отказа без мутации, повторного анализа, совместимости хэшей и benchmark 100k/1M.
  WELL-02 остаётся открытым для трёх режимов обновления и геологии с профилями поставщиков.
- 6 сентября 2026 реализован общий паспорт скважины (WELL-01): реквизиты, числовые
  значения, даты, координаты, пять строк конструкции A4 и логотипы общие для шапок;
  переводимые тексты вводятся отдельно на RU/KK/EN. Окно доступно из «Файл», «Печать»
  и редактора шапки. Миграция project v24 → v25 сохраняет старые значения и ID;
  перенос в паспорт выполняется явным выбором источника. Пустые поля активного паспорта
  не заполняются данными образца или текущего LAS. JSON/пакет сохраняют паспорт и assets.
  При проверке PDF исправлено исчезновение десятичных точек в мелком масштабируемом тексте;
  headless-печать регистрирует также настоящие полужирные шрифты Windows.

- 5 сентября 2026 утверждена модель ежедневного ведения одной скважины: один `.geologpkg`,
  общие данные и паспорт, языковые тексты RU/KK/EN, два связанных макета A4 и комплект выдачи
  из одной сохранённой ревизии. В едином плане открыты WELL-01…06 с зависимостями и критериями
  приёмки; синхронизированы требования, архитектура, политика переводов и инструкции RU/KK/EN.
  Это документирование принятого решения, а не выпуск функций: общий паспорт, дополнение
  кодовой геологии заполненных слоёв, языковые вкладки/статусы и пакетный выпуск ещё открыты.
