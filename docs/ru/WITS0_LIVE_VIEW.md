# WITS0 live monitor

## Назначение

Вкладка **Монитор** начинает отображать параметры сразу после получения первого пригодного WITS0
кадра. До запуска сессии это ограниченный по памяти **LIVE PREVIEW**, который не изменяет проект.
После подтверждения Import Review и команды **Начать сессию** накопленные preview-кадры проходят
через подтверждённую схему и переносятся в постоянный growing WITS0 Dataset. Монитор не изменяет
`AcquisitionSession`, не останавливает TCP-приём и не обходит `AcquisitionController`.

## Текущие значения

Пользователь выбирает каналы слева. Для каждого канала показываются последнее конечное значение,
единица и качество. Если в новой строке значение отсутствует, предыдущее корректное значение
остаётся видимым с состоянием `missing`. Состояние `stale` определяется по UTC-времени получения.

## Состояние потока для оператора

Верхняя строка монитора раздельно показывает режим (LIVE/LIVE PREVIEW/пауза просмотра) и состояние
текущей read-only проекции: **ОЖИДАНИЕ ДАННЫХ**, **ДАННЫЕ ПОСТУПАЮТ**,
**ДАННЫЕ УСТАРЕЛИ** либо **ЕСТЬ ОШИБКИ/РАЗРЫВЫ**. Это состояние выводится из текущих
значений и их quality, а не из предположения о состоянии сети. Для no-data tooltip предлагает
проверить TCP, рост bytes/frames и Import Review mapping; для stale — источник/сеть; для
invalid/source-gap — события и диагностику. Ошибка обновления графика не трактуется как
остановка TCP-приёма или acquisition.

## Оси времени и глубины

Режим **Автоматически** использует активный индекс Dataset. Режимы **Время** и **Глубина**
используют реальный индекс при его наличии. Если вторичной оси нет, live monitor создаёт только
read-only ось:

- UTC-время из `AcquisitionRecord.received_at`;
- глубину из подтверждённой semantic depth curve.

Производная ось не добавляется в Dataset и не сохраняется в проект.

## Auto-follow, pause-view и история

Auto-follow показывает заданное окно до последней точки. Отключение auto-follow разрешает
масштабирование и прокрутку истории. **Пауза просмотра** фиксирует количество видимых строк, но
acquisition продолжает принимать и записывать данные. Возобновление переводит представление к
актуальному хвосту.

## Downsampling

`select_visible_samples()` ограничивает количество точек в выбранном окне, сохраняет пики и
NaN-разрывы. Исходный Dataset и append-only records не изменяются. Внизу вкладки показывается
число исходных и отрисованных точек.

## Маркеры качества и разрывов

На график выводятся source-sequence gaps, большие интервалы оси, invalid values и missing spans.
Источник marker определяется из append-only record provenance. Маркеры являются диагностикой и не
заменяют решения специалиста ГТИ.

## Операторские формы и полноэкранный режим

Форму можно выбрать **до подключения**. Любая заводская форма служит исходным шаблоном, но рабочую
конфигурацию можно менять: добавлять/убирать каналы и графики, выбирать ось, окно истории и лимит
точек. Кнопка **Сохранить форму** хранит override по каноническим мнемоникам, а **Сбросить**
возвращает заводской набор. Поэтому сохранённая форма не зависит от внутренних curve ID конкретной
WITS-сессии.

Монитор адаптивный: панель параметров сворачивается, а live view можно открыть на весь экран и
вернуть в обычное окно без остановки приёма и без пересоздания runtime. При переходе LIVE PREVIEW
в постоянную запись выбранная форма и текущие несохранённые настройки оси/окна/каналов переносятся
в reviewed runtime, а не сбрасываются к factory template.

## Расчётные live-кривые и инженерные события

WITS-CALC-01 добавляет WH/BH/CH, отношения Pixler C1/C2–C1/C5 и DEXP/DEXPC как виртуальные
read-only каналы. Используется тот же versioned formula registry, что и офлайн-расчёты; Qt/UI не
содержит вторую копию формул. DEXP отображается только при валидных ROP/RPM/WOB/BIT и проверенных
единицах; DEXPC дополнительно требует фактическую и нормальную плотность раствора.

На экране отдельно показываются:

- **тип флюида по составу** — только предварительный Haworth/Pixler screening;
- **происхождение газового события** — background gas, formation show, connection gas,
  trip gas, circulated gas или elevated-unclassified;
- **threshold alarm** — выход конкретного параметра за пользовательский min/max.

Цветная линия/полоса привязана к реальной глубине или времени. Подпись рисуется горизонтальным
компактным badge у края трека. Если события расположены близко, badges автоматически раздвигаются
по уровням, но положение самой линии/полосы не изменяется.

## Min/max и сигнализация

Для каждого исходного или расчётного параметра планируется optional min/max, visual alarm,
audio alarm, hysteresis, debounce/minimum-duration и acknowledgement. Звук можно глобально
заглушить, не отключая визуальную фиксацию. Повторный звук на каждом sample запрещён: alarm
срабатывает по переходу состояния и возвращается в normal только с учётом hysteresis.

## Ограничения и приёмка

Операторский dashboard группирует совместимые каналы по технологическим панелям и автоматически
разделяет несовместимые единицы на соседние треки с независимым X-autoscale. Выбор каналов
сохраняется в workspace по canonical mnemonic, а не по session-local `curve_id`, поэтому
reconnect/новый Dataset не привязывает восстановление к старым внутренним ID. Schema-v1 с
`selected_curve_ids` читается только как migration fallback и при следующем сохранении
переписывается в schema-v2. Ось, auto-follow, pause-view и окно истории также сохраняются;
временный preview session ID не сохраняется.

Preview хранит не более 2000 последних кадров. Производный transient Dataset, curve arrays,
preview-session records и record-id index также остаются bounded: при достижении верхнего порога
runtime пересобирается из последнего окна кадров с сохранением стабильных curve IDs. Постоянная
reviewed acquisition этим механизмом не обрезается.

Если старые preview-кадры уже вытеснены из памяти, persistent backfill работает fail-closed:
кнопка старта сессии показывает число вытесненных и retained кадров вместе с доступным временным
диапазоном и не создаёт AcquisitionSession. Поэтому усечённый RAM-хвост не может быть молча
выдан за полную историю. Replay доступного raw-интервала и явный выбор более поздней границы
остаются следующей частью WITS-MEM-01.
Обязательны Windows Qt smoke test и проверка на реальном anonymized GSWITS raw-потоке.
