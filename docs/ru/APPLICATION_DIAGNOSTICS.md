# Диагностика приложения

Начиная с версии 0.7.51 GEOLOG GASRATIO@Pixler постоянно ведёт вращаемый журнал.

Команда **«Справка → Открыть папку журналов»** открывает каталог. Текущий файл называется
`geolog.log`, предыдущие версии сохраняются как нумерованные ротации. Файл `geolog-crash.log`
предназначен для faulthandler и сведений об аварийном завершении.

При проблеме используйте **«Справка → Собрать пакет диагностики…»**. ZIP содержит:

- текущий и несколько предыдущих журналов;
- версию приложения, build identity и commit SHA; если SHA нельзя доказуемо определить,
  поле содержит явное `unknown`;
- уникальный session ID текущего запуска, Python и сведения об операционной системе;
- безопасный runtime-контекст: идентификатор dataset, количество треков, состояние карандаша и
  транзакции формы.

Временные метки `geolog.log` записываются в UTC с суффиксом `Z`. В `geolog-crash.log`
каждый запуск отделяется строками `GEOLOG SESSION START/STOP` с session ID, build identity
и commit. Это позволяет отличить новый запуск от старых записей аварийного журнала и различать
две сборки одной версии пакета с разными SHA.

Release-wheel содержит неизменяемый commit stamp внутри установленного пакета. Build identity
разрешается в порядке: явное build environment → stamped package identity → VCS metadata пакета →
локальный Git checkout → явное `unknown`. Windows release gate собирает wheel, устанавливает его
в изолированное окружение вне исходного checkout и проверяет созданный diagnostic bundle без
зависимости от `.git`.

Если окно WITS0 открыто, `system-report.json` дополнительно получает только разрешённый диагностический snapshot: идентификатор/версию и SHA-256 профиля, кодировку, выбранный режим, discovery fingerprint, агрегированные счётчики capture/acquisition, стабильный код последнего отклонённого кадра и последнее суммарное число точек, фактически переданных в live-график. Адрес/порт/peer, пути raw-файлов, имя источника, значения WITS, идентификатор acquisition-сессии и свободный текст последней ошибки в этот snapshot не включаются.

Значения LAS, проектные assets, сохранённые формы и файлы проекта не добавляются. В обычных
сообщениях журнала могут присутствовать пути, названия проекта и dataset, поэтому перед передачей
пакета сторонним лицам его следует проверить.

Для воспроизводимого отчёта повторите проблемное действие, сразу создайте пакет и приложите ZIP
вместе с кратким описанием последовательности нажатий.

## Очистка накопленных данных

Команда **«Справка → Сбросить данные диагностики…»** удаляет только служебные данные,
которые приложение накопило в своём профиле:

- текущий журнал, его ротации и журнал аварийного завершения;
- сохранённые текстовые отчёты диагностики импорта;
- пустые служебные подпапки диагностики.

Перед удалением приложение показывает подтверждение и после завершения сообщает число удалённых
файлов и освобождённый объём. Журналирование автоматически запускается заново без перезапуска
программы. Проекты, LAS, пользовательские формы, настройки и ранее экспортированные пользователем
ZIP-пакеты диагностики не удаляются.

Чтобы служебный каталог не рос бесконечно, приложение автоматически оставляет не более 30 последних
отчётов диагностики импорта каждого типа.
