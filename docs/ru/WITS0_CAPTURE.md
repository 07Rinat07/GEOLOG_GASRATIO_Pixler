# Захват WITS Level 0

## Назначение

Команда **Файл → Захват WITS Level 0...** принимает поток GSWITS по TCP и сохраняет исходные
байты без изменения. Текущий срез предназначен для безопасного получения raw-дампа: он ещё не
добавляет значения в Dataset и не выполняет тревоги.

## Настройка TCP-сервера

Используйте этот режим, когда GSWITS настроен как **Исходящее соединение (TCP-клиент)**.

1. Выберите **Входящее соединение — TCP-сервер**.
2. Для приёма на всех локальных интерфейсах укажите `0.0.0.0`; для одного интерфейса укажите его IP.
3. Укажите тот же порт, на который подключается GSWITS.
4. Выберите каталог raw-данных и нажмите **Запустить захват**.
5. В GSWITS сохраните сетевые настройки и проверьте зелёный индикатор соединения.

## Настройка TCP-клиента

Используйте этот режим, когда GSWITS настроен как **Входящее соединение (TCP-сервер)**.

1. Выберите **Исходящее соединение — TCP-клиент**.
2. Укажите IP компьютера GSWITS и его порт.
3. Нажмите **Запустить захват**.
4. При разрыве Pixler автоматически повторяет подключение с увеличивающейся задержкой.

## Что сохраняется

Каждое соединение получает отдельный каталог. Binary-файлы `*.wits` содержат точные входные
байты, а `*.chunks.jsonl` фиксируют UTC-время, offset и размер каждого TCP chunk. Сегменты не
перезаписываются и пригодны для deterministic replay.

## Проверка

Вкладка **Последние пакеты** показывает frames, ограниченные `&&` и `!!`. Вкладка
**Соединения и ошибки** показывает подключение, разрыв, открытие raw-сегмента и ошибки. Закрытие
окна останавливает worker и закрывает файлы.

## Ограничения

- встроенный профиль GeoScape основан на руководстве GSWITS и требует подтверждения реальным raw;
- unknown fields не интерпретируются на этом этапе;
- WITS0-порт нельзя открывать напрямую в интернет;
- raw-файлы не заменяют сохранение проекта через **Ctrl+S** и остаются отдельными файлами.
