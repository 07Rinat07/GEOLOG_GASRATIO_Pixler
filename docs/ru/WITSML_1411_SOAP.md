# Интеграция WITSML 1.4.1.1 SOAP только для чтения

## Область реализации

Доступны только `WMLS_GetVersion`, `WMLS_GetCap` и `WMLS_GetFromStore`. Add, Update и Delete не
предоставляются. Иерархия читается в порядке:

`Well → Wellbore → Log → LogCurveInfo → LogData`.

## Граница безопасности

- URL не может содержать встроенные имя пользователя или пароль;
- пароль не сериализуется в профиле и проекте;
- в Windows используется Windows Credential Manager;
- SOAP/XML разбирается streaming-парсером с лимитами размера, глубины, элементов, текста и атрибутов;
- DTD/entity/external entity/notation отклоняются до построения полного дерева;
- размер HTTP-ответа ограничен до XML-разбора;
- аудит не содержит XML-запрос и Authorization;
- удалённый endpoint разрешён только по `https://` с проверкой цепочки сертификата и имени хоста;
- `http://` или отключение TLS verification допустимы только для loopback
  (`127.0.0.1`/`localhost`) в контролируемом тесте;
- HTTP redirects не выполняются: укажите и отдельно подтвердите окончательный URL, чтобы
  credentials не попали на другой origin или в downgrade.

При ошибке сертификата остановитесь и обратитесь к администратору сервера. Не переносите пароль
в URL и не отключайте verification для удалённого адреса.

## Повторы

Повторяются только временные сетевые ошибки и выбранные HTTP-коды. SOAP Fault и отрицательный
WITSML Result не повторяются. Каждая попытка создаёт отдельную запись аудита.

## Импорт

Строки LogData разбираются как CSV с поддержкой кавычек. Индекс выбирается по `indexCurve` либо по
первой мнемонике. `logCurveInfo/nullValue` преобразуется в null. Удалённый Log адаптируется в
`WitsmlChannelSetData`, после чего проходит существующие Import Review и атомарную регистрацию.
