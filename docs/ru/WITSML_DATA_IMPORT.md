# Импорт данных WITSML 2.x ChannelSet

## Назначение и граница

Версия 0.7.79 добавляет офлайн-парсер только для чтения и атомарный импорт bulk-данных
WITSML 2.x `Log/ChannelSet`. Парсер не изменяет XML, член EPC/ZIP или внешний файл данных. Проект
меняется только после того, как Import Review создаст полный immutable `WitsmlImportCommit` с
готовым `Dataset`, диагностикой и SHA-256 provenance.

Открытие: **Файл → Импорт данных WITSML 2.x…**. Команда инвентаря остаётся отдельной
metadata-only проверкой и не создаёт Dataset.

## Поддерживаемое представление данных

Импортер читает top-level `ChannelSet` или каждый прямой `ChannelSet` внутри WITSML `Log`.
ChannelSet должен описывать один или несколько `Index`, один или несколько `Channel` и
необязательный `ChannelData`. Bulk-строки используют JSON-совместимый layout:

```text
[
  [[index-1, index-2], [channel-1, channel-2, channel-3]],
  [[index-1, index-2], [channel-1, channel-2]]
]
```

Недостающие значения в конце короткого массива индексов или каналов дополняются `null`.
Поддерживаются встроенный `Data` и безопасный относительный `FileUri` на JSON/text. Если указаны
оба элемента, приоритет имеет `FileUri`. Binary Avro пока явно отмечается как неподдерживаемый и
не разбирается предположительно.

## Защитные ограничения

Читатель отклоняет DTD/entity, чужой namespace, неподдерживаемую schema version, абсолютный или
выходящий за корень `FileUri`, зашифрованные элементы архива, дубли путей, подозрительный
коэффициент сжатия и превышение лимитов файлов, XML-элементов, строк и ячеек. Члены ZIP/EPC
читаются в памяти и не извлекаются в произвольный путь на диске.

Структурно корректная строка сохраняется даже при некорректном индексе. Поэтому Import Review
может показать, посчитать и только по явной настройке исключить такую строку. В provenance Dataset
сохраняются SHA-256 исходного XML и массива данных.

## Import Review

Диалог позволяет оператору:

- выбрать ChannelSet из Log или пакета;
- выбрать активный временной или глубинный индекс;
- включить только требуемые scalar numeric каналы;
- проверить source mnemonic, data type и UOM;
- изменить canonical mnemonic, quantity class и target UOM;
- включить стабильную сортировку по индексу;
- определить политику строк с некорректным активным индексом;
- проверить число корректных, пустых и ошибочных значений до commit.

String, vector и point-metadata каналы видны, но по умолчанию выключены. Попытка включить
неподдерживаемый тип создаёт блокирующую ошибку. Дубли canonical mnemonic или semantic kind также
блокируют commit.

## Нормализация UOM

Численное преобразование выполняется только при наличии явной conversion family в словаре UOM.
Поддерживаются, например, `ft/h → m/h`, `ft → m`, давление, объём, расход, плотность и
электрические единицы. Единицы, которые относятся к общему классу, но не имеют универсального
преобразования, не переименовываются молча. Несовместимая или неподдерживаемая пара UOM блокирует
commit.

Временной индекс должен быть timezone-aware ISO 8601 и нормализуется в UTC `datetime64[ns]`.
Числовой индекс преобразуется тем же строгим UOM-сервисом, что и каналы.

## Атомарное создание Dataset

`WitsmlImportReviewController.commit()` заранее создаёт все массивы, metadata, semantic binding,
индексный контракт и provenance, не изменяя проект. Затем
`WitsmlProjectImportController.register()` одним действием добавляет именно тот immutable commit,
который проверил оператор. При ошибке parsing, validation или registration восстанавливаются
предыдущие current well, current Dataset и dirty state.

Dataset фиксирует:

- исходный файл/член пакета и WITSML schema version;
- UUID/key ChannelSet и выбранный index key;
- SHA-256 исходного XML и data payload;
- число исходных, импортированных и пропущенных строк;
- идентификатор layout `[[indexes],[channels]]`;
- детерминированный digest Dataset.

## Текущие ограничения

Офлайн-импорт обрабатывает только scalar numeric данные; Binary Avro и многомерные массивы не
поддерживаются. WITSML 1.4.1.1 read-only SOAP и ETP 1.2 foundation реализованы отдельными
контурами, но production ETP interoperability и Windows WITS0 field reliability gate ещё не
закрыты.
