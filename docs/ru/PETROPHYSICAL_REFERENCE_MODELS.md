# Петрофизические reference-расчёты: IGR, пористость и Archie

## Назначение и доступность

Это описание изолированного расчётного кода PR #686 (INTERP-PETRO-01), **не команды интерфейса**. В `main` до слияния PR функций нет. Модуль `geoworkbench.services.petrophysical_reference_models` принимает заранее проверенные скалярные параметры и возвращает неизменяемый результат: `method_id`, `value`, `unit`, `quality`, `parameters`. Он не выбирает LAS-мнемоники, не преобразует единицы, не привязывает MD/TVD и не изменяет проект.

## Проверка явно выбранного входа

`review_gis_reference_input(dataset, method_id=..., curve_key=...)` — отдельный
data-only API перед калибровкой. Для `igr-linear-1` требуется gamma_ray/API,
для `density-porosity-1` — bulk_density/g/cm3. Проверяется свежая инвентаризация:
MD в метрах, семантика, provenance, актуальность и фактические отсчёты.
Эквивалентное обозначение единицы допустимо, другая шкала (kg/m3 или uR/h)
отклоняется без пересчёта. Канал не подбирается автоматически.
`ready_for_calibration` не подтверждает применимость прибора/модели или
калибровку и не разрешает будущий расчёт по устаревшему review. Archie сюда
не включён: generic resistivity/neutron не доказывает Rt/эффективную пористость.
UI, исходные LAS, массивы и сохранение проекта не изменяются.

`create_gis_reference_calibration` требует calibration_id, tool_id, reviewer,
applicability_reference (основание экспертной проверки), MD-границы и все
параметры метода. `evaluate_gis_reference_sample` рассчитывает один фактический
sample_index с исходными MD/value и полным контекстом профиля. Параметров по
умолчанию, интерполяции и обрезания результатов нет. Версия кривой/metadata,
замена массива, изменение MD на месте или reopen требуют нового профиля.
Профиль session-local и не сохраняется. Основание — утверждение эксперта,
а не автоматическое доказательство применимости прибора. NaN, неверный индекс
и выход за MD-область отклоняются. Для in-place правок значений контроллер
обязан увеличить curve.version. API не предназначен для batch-цикла:
каждый отсчёт повторно проверяет inventory и MD. UI и Archie не подключены.

## Гамма-каротаж: IGR

`gamma_ray_index` (`igr-linear-1`): `IGR = (GR - GRclean) / (GRshale - GRclean)`. Все три значения — в одной проверенной шкале API; `GRshale > GRclean`. Контрольный **синтетический**, не полевой пример: `GR=65`, `GRclean=25`, `GRshale=125` API → `IGR=0.4` v/v. IGR **не равен автоматически Vsh**: минералогия, фация и локальные опоры требуют проверки. Значения вне [0,1] не обрезаются, а получают `outside_reference_range`.

## Плотностная пористость

`density_porosity` (`density-porosity-1`): `phiD = (rho_matrix - rho_bulk) / (rho_matrix - rho_fluid)`. Плотности в г/см³ задаются явно; `rho_matrix > rho_fluid > 0`. Синтетический пример: `rho_bulk=2.42`, `rho_matrix=2.71`, `rho_fluid=1.0` → `phiD≈0.16959` v/v. Отрицательный результат или значение выше 1 сохраняется с `outside_physical_range`, а не заменяется нулём. Плотность матрицы нельзя выбирать без данных о породе.

## Водонасыщенность Archie

`archie_water_saturation` (`archie-water-saturation-1`): `Sw = (a * Rw / (phi**m * Rt))**(1/n)`. Требуются явные `phi` (0 < φ ≤ 1), `Rt` и `Rw` (Ом·м), `a`, `m`, `n` (>0). Синтетический пример: `phi=0.2`, `Rt=10`, `Rw=0.1`, `a=1`, `m=2`, `n=2` → `Sw=0.5` v/v. Формула применима только после проверки типа коллектора, воды, температуры и параметров. `Sw>1` сохраняется как `outside_physical_range`, не считается доказательством флюида.

## Контроль качества и следующие работы

`valid` означает лишь допустимость численного результата при **заданных** параметрах; это не доказанная калибровка или продуктивность. Неконечные, нулевые и несовместимые входы вызывают `ValueError`; автоматических коэффициентов, порогов нефти/газа и перевода LAS-значений нет. Следующий этап — проверка provenance, единиц и глубинных осей ГИС, привязка к операторскому UI и независимая петрофизическая/полевая приёмка. Исходные значения проб и LAS-мнемоники остаются без перевода. См. [план](../PROJECT_PLAN.md) и [требования](../REQUIREMENTS.md).
